## WHAT IS CLAIMED IS:

**1.** A computer-implemented method of guiding a user through a task in a target application, the method comprising:

receiving, at a guidance client executing on a user device having a display on which the target application is rendered, a user-stated goal;

obtaining an ordered plan comprising a plurality of steps, each step comprising an instruction and a visible-when-done condition describing display content that will be present when the step has been performed;

capturing, by the guidance client, a first frame of the display;

generating, on the user device, a redacted first frame by recognizing text within the first frame, determining, by a policy engine executing on the user device, that at least one recognized text region contains sensitive information, and masking the at least one recognized text region in the first frame before the first frame is transmitted from the user device;

transmitting, from the user device to a guidance server, the redacted first frame and the plan including a status of each step;

receiving, at the guidance client, a navigation record generated using a machine-learning model having image-understanding capability from the redacted first frame and the plan, the navigation record identifying (i) any step whose visible-when-done condition is shown satisfied in the redacted first frame, (ii) a single current step, and (iii) a single instruction for the current step that references display content visible in the redacted first frame;

presenting the single instruction on the display, wherein the guidance client is configured to present the single instruction without injecting any input event into the target application, such that performance of the single instruction is reserved to the user;

capturing, by the guidance client after the presenting, a second frame of the display, generating a redacted second frame on the user device, and transmitting the redacted second frame to the guidance server; and

advancing the current step to a subsequent step of the plan only when a navigation record generated from the redacted second frame identifies the visible-when-done condition of the current step as satisfied, and otherwise presenting a corrective instruction for the current step generated from the redacted second frame.

**2.** The method of claim 1, wherein the navigation record further comprises an observation describing content of the redacted first frame and a flag that is non-empty when the redacted first frame shows an error or an incorrect value, and wherein the corrective instruction is derived from the flag.

**3.** The method of claim 1, wherein generating the redacted first frame comprises:

performing optical character recognition of the first frame on the user device to obtain a plurality of text lines each having a bounding box;

applying, to each text line, the same policy engine and the same detection rules that are applied to outbound text entered by the user, including any block word and any custom pattern defined in an egress policy applicable to the user; and

painting an opaque region over the entire bounding box of each text line in which the policy engine detects sensitive information, and re-encoding the resulting image as the redacted first frame.

**4.** The method of claim 3, further comprising, in response to the optical character recognition being unavailable on the user device, generating the redacted first frame as a downscaled copy of the first frame having a resolution at which text of the first frame is illegible, instead of transmitting the first frame at its captured resolution.

**5.** The method of claim 1, further comprising:

replacing, on the user device and before transmission, each sensitive value detected in outbound text with a placeholder token comprising a type indicator and an index;

storing a mapping between each placeholder token and the sensitive value it replaced only in volatile memory of the user device, wherein the mapping is excluded from every transmission from the user device;

receiving, at the guidance client, a response generated by the machine-learning model that contains at least one of the placeholder tokens; and

substituting, on the user device, each placeholder token in the response with the sensitive value to which it is mapped, prior to presenting the response on the display.

**6.** The method of claim 1, wherein the navigation record, when a prerequisite of the current step is absent from the redacted first frame, identifies as the current step a step that establishes the prerequisite and provides as the single instruction an action that establishes the prerequisite, and wherein the navigation record, when a control named in the current step is absent from the redacted first frame, provides as the single instruction an action directed to a different control visible in the redacted first frame that performs an equivalent function, together with an indication that the target application differs from the plan.

**7.** The method of claim 1, wherein the machine-learning model is a first model, the method further comprising determining that an output of the first model lacks each of an instruction, an identification of a satisfied step, a current step, and an observation, and in response re-submitting the redacted first frame and the plan to a second model having greater capability than the first model to generate the navigation record, and recording the re-submission in a session event log visible to the user.

**8.** The method of claim 1, further comprising, in response to the navigation record generated from the redacted second frame identifying the visible-when-done condition of the current step as satisfied for the first time, storing the redacted second frame, as already generated on the user device for transmission, as evidence of the current step in association with a timestamp, such that no frame other than the redacted second frame is transmitted or stored for the evidence.

**9.** The method of claim 8, further comprising generating a session report comprising, for each step whose visible-when-done condition was identified as satisfied, the timestamp, any command or code included in the step, and the stored redacted frame as an exhibit, and comprising, for each step not identified as satisfied, only a name and status of the step, wherein the session report and each stored redacted frame are encrypted at rest.

**10.** A system comprising:

a guidance server; and

a guidance client configured to execute on a user device having a display, an input device, and a target application rendered on the display, the guidance client comprising:

 a capture module configured to capture frames of the display;

 a policy-enforcement module configured to hold an egress policy specifying, for each of a plurality of categories of sensitive information, an action selected from at least redacting and tokenizing;

 an on-device redaction engine configured to recognize text within each captured frame, identify, according to the egress policy, text lines containing sensitive information, and mask the identified text lines to produce a redacted frame before the frame leaves the user device;

 a tokenizer configured to replace, in outbound text, each sensitive value whose category action is tokenizing with a placeholder token comprising a type indicator, and to store a mapping between each placeholder token and the replaced sensitive value in a token map held only in volatile memory of the user device and excluded from every transmission;

 a presentation layer configured to present, on the display, a single instruction for a current step of an ordered plan without injecting any input event into the target application; and

 a local rehydration module configured to substitute, on the user device, each placeholder token appearing in a response received from the guidance server with the sensitive value to which it is mapped in the token map;

wherein the guidance server is configured to receive the redacted frame and the plan from the guidance client, to obtain from a machine-learning model having image-understanding capability a navigation record identifying any step of the plan whose visible-when-done condition is shown satisfied in the redacted frame, a single current step, and the single instruction for the current step referencing content visible in the redacted frame, and to advance the current step only when a subsequently received redacted frame yields a navigation record identifying the visible-when-done condition of the current step as satisfied.

**11.** The system of claim 10, wherein the tokenizer is configured to map an identical sensitive value to an identical placeholder token throughout a session, such that repeated references to the sensitive value in outbound text and in responses are represented by a single placeholder token.

**12.** The system of claim 10, wherein the local rehydration module is configured to apply the substitution to each partial chunk of a streamed response as the chunk is received, such that a rehydrated response is presented progressively.

**13.** The system of claim 10, wherein the local rehydration module is configured, when a placeholder token present in the token map is absent from or altered in the response, to leave the response unmodified at that location and to present an indication that the response is incomplete at that location, without substituting any value not present in the token map.

**14.** The system of claim 10, wherein the egress policy further specifies a plurality of block words, and wherein the on-device redaction engine and the tokenizer are each configured to remove every occurrence of each block word, from recognized text lines of captured frames and from outbound text respectively, irreversibly and without creating any placeholder token.

**15.** The system of claim 10, wherein the guidance server further comprises a security gate configured to match each command and each code block included in any step of the plan against a catalog of destructive-operation patterns and to annotate a matching step with a destructive indicator and a reason, and wherein the presentation layer is configured to withhold display of the command or code block of an annotated step until the user provides an explicit acknowledgment.

**16.** A non-transitory computer-readable medium storing instructions that, when executed by one or more processors of a guidance server and of a user device, cause performance of operations comprising:

storing, for a tenant comprising a plurality of member users, an egress policy object comprising (i) for each of a plurality of categories of sensitive information, an action selected from sending, redacting, withholding and tokenizing, (ii) a set of block words, (iii) a mode selecting between redaction and tokenization, (iv) a screenshot-evidence setting indicating whether redacted frames of member displays may be retained, and (v) an armed state;

distributing the egress policy object, when armed, to a guidance client executing on the user device of each member user;

capturing, by the guidance client on the user device of a member user, frames of a display on which a target application is rendered, and, for each frame, recognizing text within the frame and masking, before the frame leaves the user device, each text line that the egress policy object identifies as containing sensitive information or a block word, to produce a redacted frame;

transmitting the redacted frame and an ordered plan of steps, each step having a visible-when-done condition, to the guidance server;

obtaining, by the guidance server from a machine-learning model having image-understanding capability, a navigation record identifying any step whose visible-when-done condition is shown satisfied in the redacted frame, a single current step, and a single instruction for the current step;

presenting the single instruction on the display without injecting any input event into the target application, and advancing the current step only when a subsequently received redacted frame yields a navigation record identifying the visible-when-done condition of the current step as satisfied;

storing the redacted frame as evidence of a step only when the navigation record identifies the step as newly satisfied and only when the screenshot-evidence setting permits retention, and otherwise retaining no frame; and

appending to an audit log, for each transmission from the user device, a record comprising a version of the egress policy object in force, the mode, a count of items removed in each category, and whether a frame was transmitted, the record excluding every sensitive value removed.

**17.** The non-transitory computer-readable medium of claim 16, wherein the egress policy object further comprises a locked state, and the operations further comprise refusing any modification of the egress policy object while in the locked state unless the modification is accompanied by an explicit unlock that requires re-authentication of an administrator having a privilege level above that of a tenant administrator and that creates an entry in the audit log.

**18.** The non-transitory computer-readable medium of claim 16, wherein the operations further comprise denying, to each member user of the tenant, any request to modify, disable or weaken the egress policy object on the member user's user device, and re-applying the egress policy object at the guidance server to content received from the user device.

**19.** The non-transitory computer-readable medium of claim 16, wherein the egress policy object further comprises a retention window, and the operations further comprise periodically deleting each session of the tenant older than the retention window together with every redacted frame stored as evidence for the session and the audit log of the session, in a single operation.

**20.** The non-transitory computer-readable medium of claim 16, wherein the guidance client is a web application executing in a browser without installation, the single instruction is presented in a browser-native picture-in-picture document window positioned above the target application, and the frames are captured through a display-media capture interface of the browser; or wherein the guidance client executes in a desktop shell whose window is configured as always-on-top with a click-through mode and content protection such that the window is excluded from the captured frames and from screen sharing by other applications.
