## WHAT IS CLAIMED IS:

**1.** A computer-implemented method of guiding a user through a task in a target application, the method comprising:

receiving, at a guidance client executing on a user device having a display on which the target application is rendered, a user-stated goal;

obtaining an ordered plan comprising a plurality of steps generated by a planning machine-learning model from the user-stated goal, each step comprising an instruction and a visible-when-done condition, the visible-when-done condition being generated by the planning machine-learning model together with the plan and describing display content that will be present on the display when the step has been performed;

capturing, by the guidance client, a first frame of the display;

generating, on the user device, a redacted first frame by recognizing text within the first frame, determining, by a policy engine executing on the user device, that at least one recognized text region contains sensitive information, and masking the at least one recognized text region in the first frame before the first frame is transmitted from the user device;

transmitting, from the user device to a guidance server, the redacted first frame and the plan including a status of each step;

receiving, at the guidance client, a navigation record generated using a machine-learning model having image-understanding capability from the redacted first frame and the plan, the navigation record identifying (i) each step of the plan whose visible-when-done condition is shown satisfied in the redacted first frame, (ii) a single current step, and (iii) a single instruction for the current step that references display content visible in the redacted first frame;

presenting the single instruction on the display, wherein the guidance client is configured to present the single instruction without injecting any input event into the target application, such that performance of the single instruction is reserved to the user;

capturing, by the guidance client after the presenting, a second frame of the display, generating a redacted second frame on the user device, and transmitting the redacted second frame to the guidance server;

advancing the current step to a subsequent step of the plan only when a second navigation record generated from the redacted second frame and the plan identifies the visible-when-done condition of the current step as satisfied by display content present in the redacted second frame, and otherwise presenting a corrective instruction for the current step derived from the second navigation record; and

in response to the second navigation record identifying the visible-when-done condition of the current step as satisfied, retaining the redacted second frame, as generated on the user device for the transmitting, as evidence of the current step, such that no frame other than the redacted second frame is transmitted or stored as the evidence.

**2.** The method of claim 1, wherein generating the redacted first frame comprises:

performing optical character recognition of the first frame on the user device to obtain a plurality of text lines each having a bounding box;

applying, to each text line, the policy engine and a set of detection rules, the policy engine and the set of detection rules being the same policy engine and the same set of detection rules that are applied on the user device to outbound text entered by the user, including each block word and each custom pattern defined in an egress policy applicable to the user; and

painting an opaque region over the entire bounding box of each text line in which the policy engine detects sensitive information or a block word, and re-encoding the resulting image as the redacted first frame.

**3.** The method of claim 2, further comprising, in response to the optical character recognition being unavailable on the user device, generating the redacted first frame as a downscaled copy of the first frame having a resolution at which text of the first frame is illegible, instead of transmitting the first frame at its captured resolution, wherein the resolution is selected according to a legibility criterion comprising at least one of: an estimated height of a smallest text run of the first frame falling below a threshold height after downscaling; and a recognition pass over the downscaled copy returning no text run above a confidence threshold.

**4.** The method of claim 1, further comprising:

replacing, on the user device and before transmission, each sensitive value detected in outbound text with a placeholder token comprising a type indicator and an index, an identical sensitive value being replaced by an identical placeholder token throughout a session;

storing a mapping between each placeholder token and the sensitive value it replaced only in volatile memory of the user device, wherein the mapping is excluded from every transmission from the user device;

receiving, at the guidance client, a response generated by the planning machine-learning model or by the machine-learning model having image-understanding capability, the response containing at least one of the placeholder tokens; and

substituting, on the user device, each placeholder token in the response with the sensitive value to which it is mapped, prior to presenting the response on the display.

**5.** The method of claim 1, wherein, when a prerequisite of a step of the plan that would otherwise be the current step is absent from the redacted first frame, the navigation record identifies as the single current step a step that establishes the prerequisite, provides as the single instruction an action that establishes the prerequisite, and identifies the prerequisite that was absent.

**6.** The method of claim 1, wherein, when a control named in the current step is absent from the redacted first frame and a different control that performs an equivalent function is visible in the redacted first frame, the navigation record provides as the single instruction an action directed to the different control together with an indication that the target application differs from the plan, the method further comprising at least one of: recording the indication in a session record of the task; and supplying the indication to the planning machine-learning model as an input to a regeneration of at least one remaining step of the plan.

**7.** The method of claim 1, wherein the retaining is performed only in response to the first navigation record that identifies the visible-when-done condition of the current step as satisfied, the redacted second frame being stored in association with a timestamp of that identification and only when a screenshot-evidence setting of an egress policy applicable to the user permits retention, the method further comprising generating a session report comprising, for each step whose visible-when-done condition was identified as satisfied, the timestamp, any command or code included in the step and the stored redacted second frame as an exhibit, and comprising, for each step not identified as satisfied, only a name and a status of the step.

**8.** The method of claim 1, further comprising:

receiving, at the guidance client, a clarification question generated by the planning machine-learning model together with the plan, the clarification question comprising a plurality of answer options inferred from display content of a frame of the display captured by the guidance client and redacted on the user device, wherein the clarification question is withheld when an answer to the clarification question is determinable from the display content;

presenting the clarification question on the display together with the answer options, a free-text entry and a skip control;

storing, in a session scope, an answer received through the answer options or the free-text entry, or a record that the skip control was operated together with a stated assumption on which planning is to proceed; and

transmitting, from the guidance client to the guidance server, a plan regeneration request carrying a clarification-origin indicator, wherein the guidance server regenerates the plan from the session scope in response to the plan regeneration request without decrementing a per-task regeneration limit that is decremented by a user-initiated plan regeneration request that lacks the clarification-origin indicator.

**10.** The system of claim 9, wherein the local rehydration module is configured, when a placeholder token present in the token map is absent from or altered in the response, to leave the response unmodified at that location, to present an indication that the response is incomplete at that location, and to substitute no value that is not present in the token map, the token map being consulted only by exact match.

storing the project map together with a learnings ledger of generalized facts scoped to the project;

appending to the learnings ledger, in association with the selected task descriptor, at least one generalized fact derived from the obtaining of the ordered plan of steps or from the guiding, the appending being deduplicated against existing entries of the learnings ledger by normalized comparison of fact text;

upon completion of the guiding for the selected task descriptor, marking the selected task descriptor as being in the done state and recording for the selected task descriptor an outcome comprising a count of the steps whose visible-when-done conditions were identified as satisfied;

repeating the selecting, the obtaining of an ordered plan of steps, the guiding, the appending and the marking for each remaining task descriptor of the project map, such that the ordered plan of steps for a later task descriptor is generated from generalized facts appended during earlier task descriptors of the same project; and

declaring the project complete only when every task descriptor of the project map is in the done state and the project end-state is shown satisfied.

**20.** The method of claim 19, further comprising, before the storing, applying to the project map a deterministic gate that invokes no machine-learning model, the deterministic gate:

counting as real only those task descriptors that have both a task goal and a non-empty done-state;

normalizing a label of each task descriptor, the label being the task goal or, when the task goal is empty, a title of the task descriptor, and collapsing task descriptors whose normalized labels are equal to a single task descriptor before counting;

rejecting the project map and returning the project goal to the human performer as a single task when fewer than two distinct real task descriptors remain after the collapsing;

rejecting the project map when any task descriptor is not real, when any dependency references a task descriptor absent from the project map, when the dependencies of the task descriptors form a cycle, or when the project end-state is empty, each failing condition being reported together with every other failing condition; and

producing, when an ordered plan of steps obtained for a single task descriptor comprises more steps than a threshold, an advisory indication only and never a division of that task descriptor into a plurality of task descriptors.

**A1 (II-1, method).** A computer-implemented method of generating a guidance plan for a human performer, comprising:

receiving a goal statement and an application identifier from a requesting user, and an environment description of the requesting user's session comprising at least one of a jurisdiction, a list of named software and a manual-versus-software indicator;

computing a goal signature of the goal statement, the goal signature being an ordered token set produced by lowercasing the goal statement, removing email addresses, uniform resource locators and possessives, removing tokens that are purely numeric or version-like, removing stop words, applying singularization and removing duplicate tokens;

for each workflow template in a store scoped to a holder of the requesting user, each workflow template comprising a stored goal signature, a stored application key, a stored environment record and ordered steps, computing (i) a goal similarity equal to a mean of a Jaccard index and an overlap coefficient of the goal signature and the stored goal signature, (ii) an application similarity that treats the application identifier and the stored application key as matching when they are equal or when one is a token subset of the other, and (iii) an environment compatibility score that is reduced by each contradiction between the environment description and the stored environment record, a contradiction being a differing jurisdiction, a disjoint list of named software or a conflicting manual-versus-software indicator, and an attribute absent from the environment description never contradicting;

forming a weighted combination of the goal similarity, the application similarity and the environment compatibility score;

classifying a best-scoring workflow template into a serving tier only when the weighted combination meets a first floor, the application similarity indicates a match, no contradiction exists and the environment compatibility score meets an environment floor; into a seeding tier when the weighted combination meets a second floor lower than the first floor and the best-scoring workflow template was not classified into the serving tier; and otherwise withholding the best-scoring workflow template; and

generating the guidance plan by adapting the ordered steps of a serving-tier workflow template to the environment description in a single adaptation pass of a language model, the single adaptation pass comprising supplying the serving-tier workflow template to the language model together with a directive to follow the serving-tier workflow template as the backbone of the guidance plan and to adapt it only where the environment description differs from the stored environment record, by supplying a seeding-tier workflow template to a planning language model as context for a planning pass, or, when the best-scoring workflow template is withheld, by the planning pass without any workflow template, wherein each step of the guidance plan is presented to the human performer one step at a time and is verified against a captured frame of the human performer's display before a subsequent step is presented.

**A2 (II-2, computer-readable medium).** A non-transitory computer-readable medium storing instructions that, when executed by one or more processors, cause performance of operations comprising:

maintaining, for a guided session in which a human performer performs each step of an ordered plan in a target application and each step carries a done status that is set only when a captured frame of the human performer's display shows a visible-when-done condition of the step satisfied, a session record comprising a goal statement, scoping answers, the ordered plan with the done status of each step, and an event log;

on completion of the guided session, evaluating a clean-success predicate that is satisfied only when the ordered plan has at least one step, every step carries the done status, and a final event of the event log is not an unresolved flag;

in response to the clean-success predicate being satisfied, deterministically generating, without invoking any machine-learning model, a workflow template comprising a goal signature derived from the goal statement with numeric and version-like tokens removed, a normalized application key, an environment record derived from the scoping answers and comprising a jurisdiction, a list of named software and a manual-versus-software indicator, ordered steps each comprising a step kind selected from command, code, navigate and user-interface action and a first on-screen target named in guidance for the step, and a success signal equal to the visible-when-done condition of a last step;

applying a pre-scrub to prose fields of the workflow template that removes email addresses and digit runs, command and code content of the ordered steps being exempt from the pre-scrub;

at persistence, applying to every string value of the workflow template a policy-driven scrub under a stored policy of a holder of the human performer, the scrub preserving keys of the workflow template and applying a full scrub when no stored policy is present; and

storing the workflow template in a store scoped to the holder, the store being a private store of a tenant when the human performer belongs to the tenant and otherwise a shared de-identified store, wherein a tenant-level switch disables both storing into and retrieval from the store.

**A3 (III-1, system).** A system comprising one or more processors and memory storing instructions that configure the one or more processors to:

store, for a tenant comprising a plurality of member users, a single policy object comprising, for each of a plurality of categories of sensitive information, an action selected from sending, redacting, withholding and tokenizing, a set of block words, a mode selecting between redaction and tokenization, a screenshot-evidence flag, and an armed state;
